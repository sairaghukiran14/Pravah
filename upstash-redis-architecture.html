End-to-End Request Execution & Evaluation Flow

Sequence diagram showing token evaluation, deduction, and automatic retry timing:

sequenceDiagram
    autonumber
    actor Client as User / Frontend
    participant Route as route.ts (API Gateway)
    participant Limiter as rateLimit.ts
    participant Redis as Upstash Redis (REST)
    participant Core as API Core Logic (AI / DB)

    Client->>Route: POST /api/pipelines/run (Payload: 25 Tokens)
    Route->>Route: Validate NextAuth Session -> userId = 'usr_789'
    
    Route->>Limiter: consumeRateLimit("user:usr_789", cost: 25)

    alt Redis Cloud is Reachable
        Limiter->>Redis: POST /limit { id: "pravah:rl:user:usr_789", rate: 25 }
        Redis-->>Limiter: { success: true, remaining: 95, reset: 1726075900 }
    else Redis Cloud Unreachable
        Limiter->>Limiter: localConsume(id, cost: 25) via globalThis Map
    end

    alt Check Passed (Tokens >= 25)
        Limiter-->>Route: { success: true, remaining: 95 }
        Route->>Core: Execute Pipeline Workflow (Sarvam AI STT/TTS)
        Core-->>Route: Return Audio & Translation Output
        Route-->>Client: HTTP 200 OK + Payload
    else Rate Limit Exceeded (Tokens < 25)
        Limiter-->>Route: { success: false, remaining: 8, reset: 1726075920 }
        Route-->>Client: HTTP 429 Too Many Requests
(Retry-After: 20 seconds)
    end

Identifier Resolution & Anti-Spoofing Flow

flowchart TD
    REQ[Incoming Request Headers] --> AUTH{Is Session Authenticated?}
    
    AUTH -- Yes --> USER["Key: `user:${session.user.id}`\n(Cryptographically Verified, Unspoofable)"]
    
    AUTH -- No --> IPCHECK["Inspect Proxy Headers in Order:\n1. `x-real-ip` (Edge Injected)\n2. `x-forwarded-for` (Right-to-Left Walk)"]
    
    IPCHECK --> FILTER{"Is IP Private/Loopback?\n(10.x, 192.168.x, 127.x, ::1)"}
    FILTER -- Yes --> SKIP[Skip Spoofed Client IP]
    FILTER -- No --> SAFEIP["Key: `ip:${safeClientIp}`"]
    
    USER --> LIMITER[Upstash Redis Sliding Window]
    SAFEIP --> LIMITER
Security Benefit: Authenticated users cannot bypass rate limiting by changing IP addresses or rotating headers, because their token bucket is bound directly to their verified userId.
