📖 What is Pravah?

Pravah is a full-stack visual workflow studio that lets users drag-and-drop AI building blocks onto an infinite canvas, connect them with wires, and click "Run" to execute entire multi-step Indian language AI pipelines — without writing backend code.

💡
Think of it as Figma meets Zapier, but for Indian Language AI. Drop an Audio Upload box → connect to Speech-to-Text → Translate → AI Voice → Run → get your translated audio in seconds.

🏛️ Master System Architecture Diagram

Complete 6-tier architecture with data flows and interconnections:

🖥️ Tier 1 — Client & Canvas (Next.js 16 + React 19)

  • React Flow (@xyflow/react) infinite canvas with 25+ custom AI node types across 7 categories
  • Zustand 5 state machine with 30-state deep-cloned undo/redo ring buffer (⌘Z / ⌘⇧Z)
  • Command Palette (⌘K) with fuzzy search & layered BFS DAG auto-layout ("Tidy DAG")
  • In-browser 16kHz mono 16-bit PCM WAV encoder from Web Audio API Float32Array buffers
  • AI Pipeline Generator: natural language / voice description → auto-configured DAG preview

🛡️ Tier 2 — Defensive Security Gateway

  • Edge Middleware: intercepts /dashboard, /pipeline, /profile → verifies session cookie or redirects
  • NextAuth v5 (Google OAuth + Credentials) with instant revocation via User.sessionsRevokedAt
  • route.ts wrapper: all routes are authenticated by default — must explicitly set auth: false to open
  • Upstash Redis sliding-window rate limiter: 120 cost-weighted tokens per 60s per user/IP

⚙️ Tier 3 — Topological DAG Execution Engine & Realtime SSE

  • Kahn's Algorithm: computes in-degree map → linearizes topological execution order
  • Dynamic variable resolver: substitutes {{nodeId.property}} from upstream outputs before dispatch
  • Router/conditional gate: evaluates rules, disables dead-end edges, propagates skip to descendants
  • SSE Streamer (text/event-stream): run_started → node_started → node_completed → run_completed

🌐 Tier 4 — Sarvam Indic AI

  • Saaras:v3 STT (auto 30s chunking)
  • Bulbul:v3 TTS (sentence slicing)
  • Mayura:v1 Translation (22+ langs)

  • Document AI OCR (multipage)
  • fetchWithRetry (backoff + 25s abort)

💳 Tier 5 — Financial Ledger

  • Razorpay order + HMAC-SHA256 verify
  • Upfront RUN_RESERVATION hold
  • Per-second / per-char / per-page metering
  • Atomic settlement & refund
  • Stale-run auto-reaper (15 min timeout)
  • 500 credit/day blast-radius ceiling

🗄️ Tier 6 — Storage & Database Persistence

  • Neon Serverless PostgreSQL via Prisma 6 ORM — 15 models (Users, Pipelines, Runs, Ledger, Evals)

  • Upstash Redis — distributed rate limit buckets (sliding window, 120 tokens/min, cost-weighted)

🧠 Architecture Decisions & Approaches

Every major technical choice was made deliberately. Below are the 8 core decisions, why each alternative was rejected, and the trade-offs accepted.

Decision 1

Server-Sent Events (SSE) over WebSockets for Execution Streaming

Approach: Unidirectional text/event-stream via standard HTTP POST response.

Why Pipeline runs are short-lived (2–45s). A full duplex WebSocket adds connection setup overhead for a single burst. SSE maps natively to serverless HTTP lifecycles with no socket leak risk.

Rejected WebSockets — require persistent connection, break on Vercel's 60s serverless ceiling, and need explicit reconnection logic. SSE reconnects natively via browser EventSource protocol.

Decision 2

Opt-Out Security Wrapper (Secure by Default)

Approach: Generic route<TBody, TQuery>() wrapper in src/lib/api/route.ts that enforces authentication, rate limiting, and Zod validation on every endpoint.

Why A developer must explicitly write auth: false to expose a public route. This structural convention prevents unauthenticated data exposure if a new route file is created without manual verification code.

Rejected Opt-in middleware per route — high risk of forgotten auth checks on new endpoints, especially under deadline pressure.

Decision 3

2-Phase Atomic Credit Reservation → Settlement

Approach: Before any paid work, atomically hold RUN_RESERVATION (configurable, default 10 credits) from the wallet. After the run, refund the unused difference.

Why Prevents double-spending race conditions: a user with 15 credits cannot trigger two ₹10 runs simultaneously because the atomic SQL WHERE credits >= 10 serializes on the row.

Rejected Post-execution billing — if the server crashes mid-run, the user consumes paid API calls without ever being charged. The hold-first model ensures revenue is never lost.

Decision 4

Topological DAG Engine (Kahn's Algorithm) for Execution Order

Approach: Parse the visual graph into an adjacency list, compute in-degree, and linearize execution schedule. Router nodes prune dead-end branches; only live paths execute.

Why Guarantees a Translation node never runs before its upstream STT node produces text. Independent branches (e.g., two separate STT streams) can execute in parallel safely.

Rejected Simple linear queue — cannot parallelize independent branches, and has no concept of conditional routing or dead-edge pruning.

Decision 5

Private R2 Storage Gateway with Range-Request Proxy

Approach: Audio and document artifacts are stored in a private Cloudflare R2 bucket with zero public read access. A Next.js route (/api/audio/[filename]) validates the user's session and streams only the requested byte range.

Why User-generated audio recordings and OCR outputs may contain sensitive PII. Public URLs would expose them to anyone with the link. Range streaming enables instant audio seeking without downloading full multi-MB files.

Rejected Signed URLs with expiry — still expose the file to anyone who intercepts the URL during its validity window. The proxy ensures every access is session-verified.

Decision 6

In-Browser PCM WAV Encoding over Compressed WebM

Approach: Capture raw Float32Array samples via Web Audio API and write a 44-byte RIFF/WAVE header at 16kHz mono, producing an audio/wav blob in-memory.

Why Browser MediaRecorder produces compressed WebM chunks that cannot be byte-sliced at sentence boundaries. Uncompressed WAV allows clean 30s chunking for Sarvam's STT endpoint without re-encoding.

🧠 Architecture Decisions (continued)

Decision 7

Cost-Weighted Rate Limiting (Not Per-Request)

Approach: Upstash Redis sliding-window rate limiter consumes variable "cost" tokens per request. A pipeline run costs 25 tokens; a profile read costs 1 token. Budget: 120 tokens per 60 seconds per user.

Why A pipeline run fans out into a dozen paid Sarvam calls, while a profile read hits only our DB. Treating both as "one request" under-protects the expensive operation. Cost-weighting prevents API abuse while allowing normal browsing.

Rejected Flat per-request limiting — a user could exhaust all Sarvam quota by triggering 120 pipeline runs/minute while reading a single profile page also counted equally.

Decision 8

Stale Run Auto-Reaper Daemon

Approach: Before each new run, sweep the user's pipeline runs stuck in running status for over 15 minutes. Claim their reservation (atomically — prevents double-refund), mark as failed, and refund held credits.

Why Serverless functions killed at Vercel's timeout boundary never reach the finally block. Without the reaper, those runs would hold credit permanently and block the user's 3-run concurrency limit forever.

Claim mechanism Both the settlement logic and the reaper try to clear PipelineRun.reservedCredits via updateMany WHERE reservedCredits IS NOT NULL. Only the first caller succeeds — the second becomes a no-op. This eliminates all double-refund race conditions.

💳 Revenue Model & Unit Economics

Pravah operates on a pre-paid credit wallet model with Razorpay-powered top-ups. The margin is built into the per-node pricing (1.5× wholesale cost).

Revenue Sources

  • Credit Top-Ups: Users purchase credits via Razorpay (UPI, card, netbanking). Range: ₹1 – ₹1,00,000 per transaction.
  • Free Tier: Every new user receives 20 free credits on sign-up to encourage trial.
  • Markup: Node pricing is set at ~1.5× Sarvam's wholesale billing rate (e.g. STT = 0.375 cr/30s vs Sarvam's ₹30/hour).

Cost Structure (Per Run)

  • Sarvam API Costs: The primary COGS — billed per audio second, per text character, and per document page.
  • Infrastructure: Neon PostgreSQL (serverless), Cloudflare R2 (object storage), Upstash Redis (rate limits), Vercel (compute).
  • Payment Gateway: Razorpay charges 2% per transaction on top-ups.

⚙️ Pipeline Execution — Step-by-Step Sequence

When a user clicks "Run Pipeline" (or presses ⌘ Enter):

Client Sends Run Request

Browser sends POST /api/pipelines/[id]/run with pipeline payload and node input overrides.

Gateway Validates & Rate Limits

route.ts verifies NextAuth session, consumes rate limit tokens (cost: 25), validates body via Zod schema.

Credit Reservation (Phase 1 — Hold)

Atomically deduct 10 credits as upfront hold. Check daily ceiling (500 cr/24h). Check concurrency limit (max 3 active runs). If insufficient: reject with 402.

Topological Sort & Graph Linearization

Kahn's algorithm computes in-degree, detects cycles, produces execution schedule. SSE stream opens: event: run_started.

Node-by-Node Execution (Topological Order)

For each node: resolve {{stt_1.transcript}} variables → stream node_started → dispatch to Sarvam → upload media to R2 → persist NodeRun → stream node_completed with output, duration, and cost.

Credit Settlement (Phase 2 — Refund)

Compute actual cost (e.g. 3.38 cr). Refund: 10.00 − 3.38 = +6.62 credits. Record CreditTransaction. Stream event: run_completed. Close stream.

Event NameWhen EmittedKey Payload Fields

node_startedBefore each node executesnodeId, nodeType, label
node_completedAfter a node succeedsnodeId, output, durationMs, cost

⚠️
Client Cancellation: If the user aborts mid-run, the browser's AbortController.abort() fires. The server's finally block detects stream closure and immediately calls settleCredits() — refunding the full unused reservation. No credits are lost.
